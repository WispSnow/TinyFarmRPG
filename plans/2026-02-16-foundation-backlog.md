# TinyFarmRPG 地基重构 Backlog（2026-02-16）

## 目标与范围
- 目标：在不扩玩法体量的前提下，先完成可持续扩展的“地基重构”，为以下能力做准备：
  - Lua + Sol2 脚本化
  - RPG 玩法扩展（商店、任务线、回合制战斗、技能）
  - 角色分层换装（衣服/头发/武器等）
  - 粒子特效系统（Effekseer）
- 执行窗口：`2026-02-16` ～ `2026-03-08`（3 周）
- 当前质量基线：`ctest --test-dir build` 通过 `126/126`（3 个音频测试为 skip）

## 非目标（本阶段不做）
- 不做完整战斗玩法内容实现（只做战斗框架与接入点）
- 不做大量剧情/任务脚本填充（只做脚本宿主与示例）
- 不做大量美术资源改造（只做换装数据结构与渲染能力）

## 完成定义（DoD）
- 每个 backlog 项都满足：
  - 对应代码有测试覆盖（新增或更新）
  - 关键设计决策落文档（`docs/` 或本文件附录）
  - 现有回归测试保持通过（`ctest --test-dir build`）
  - 不引入“必须手工维护”的隐式顺序耦合

## 优先级约定
- `P0`：必须完成，否则后续扩展会反复返工
- `P1`：强烈建议完成，影响后续开发速度与稳定性
- `P2`：可延后，属于优化项

## Sprint 1（第1周）：运行时解耦与调度收口

### FND-001（P0）拆分 GameScene 装配职责
- 目标：把 `GameScene` 从“全能组合根”拆成更小的 runtime 组装单元。
- 主要改动：
  - 新建 `game/runtime/`（建议：`game_runtime.h/.cpp`, `system_graph.h/.cpp`）
  - 从 `GameScene` 挪出系统创建与依赖注入逻辑
  - `GameScene` 仅保留场景生命周期与少量编排
- 验收标准：
  - `src/game/scene/game_scene.cpp` 行数显著下降（目标 `< 500`）
  - 初始化顺序通过单测或集成测试锁定
  - 现有场景流（Title -> Game -> Pause -> Save/Load）行为不变

### FND-002（P0）引入显式 SystemScheduler + GameMode
- 目标：把“系统更新顺序”从硬编码改为可声明、可切模式。
- 主要改动：
  - 增加 `GameMode`（`Exploration / Battle / PauseOverlay / Cutscene`）
  - 建立 `SystemScheduler`（按 mode 选择系统集合与顺序）
  - 保留现有探索模式逻辑顺序作为默认 profile
- 验收标准：
  - 切图过渡期间冻结逻辑仍正确
  - 可通过一个入口切换 mode（即使 Battle 还未完整实现）
  - 增加至少 2 个顺序相关测试（例如移动->空间索引、时间->光照）

### FND-003（P0）建立 Command -> DomainEvent 边界
- 目标：减少 UI 直接触发业务事件造成的耦合，统一“请求”和“结果”。
- 主要改动：
  - 新增 `game/defs/commands.h`
  - UI/输入层优先发 `Command`，系统处理后再发 `DomainEvent`
  - 先覆盖高频链路：`Inventory/Hotbar/Interact/UseItem`
- 验收标准：
  - 现有 UI 行为不回退（背包、快捷栏、交互、使用物品）
  - 事件命名语义更清晰（请求 vs 结果）
  - 关键链路有回归测试

### FND-004（P1）日志与调试可视化补强
- 目标：让后续重构和新系统接入更容易定位问题。
- 主要改动：
  - 为 scheduler 增加“每帧阶段日志（trace 级）”
  - Debug 面板显示当前 mode、系统耗时摘要
- 验收标准：
  - 不开启 debug 时无额外运行时开销
  - 可在 debug 面板看到系统执行顺序与 mode

## Sprint 2（第2周）：数据与脚本地基

### FND-005（P0）存档升级到 Schema v3 + 迁移器
- 目标：为任务/技能/外观/战斗状态预留稳定存档位，避免未来破档。
- 主要改动：
  - `SAVE_SCHEMA_VERSION` 从 `2` 升到 `3`
  - 新增迁移入口：`v1/v2 -> v3`
  - 新增空结构字段（可先默认值）：
    - `quest_state`
    - `skill_state`
    - `appearance_state`
    - `combat_state`（仅框架态）
- 验收标准：
  - 旧档可读（至少覆盖 v2 -> v3）
  - 新档可写且可回读一致
  - 新增迁移与回读测试

### FND-006（P0）引入 Lua + Sol2 宿主层（最小可用）
- 目标：先接脚本运行时，不急着大规模脚本化。
- 主要改动：
  - CMake 接入 Lua 与 Sol2（建议可选开关：`ENABLE_SCRIPTING`）
  - 新建 `ScriptHost`（加载/执行/错误处理/热重载入口）
  - 暴露最小 API：读时间、读玩家、发 command、弹文本
- 验收标准：
  - 能加载并执行一个脚本文件
  - 脚本报错不会崩溃主循环（有错误日志）
  - 至少 1 条脚本驱动链路跑通（例：对话后发奖励 command）

### FND-007（P1）脚本安全边界与资源生命周期
- 目标：防止脚本越权和悬垂引用。
- 主要改动：
  - 只暴露白名单 API（不直接暴露 registry 原始写入）
  - 统一脚本对象句柄（entity handle 校验）
  - 场景切换时脚本上下文回收策略明确
- 验收标准：
  - 场景切换后脚本调用失效对象会被安全拦截
  - 无裸指针跨场景悬挂

## Sprint 3（第3周）：扩展能力接入点（非完整玩法）

### FND-008（P0）角色分层外观模型（先框架）
- 目标：从单 Sprite 模型过渡到可组合层模型，为换装铺路。
- 主要改动：
  - 新增 `AppearanceComponent`（slots + layer order + asset ids）
  - 渲染侧支持同一角色多层提交（身体/头发/衣服/武器）
  - 动画帧同步策略（同一骨架帧号驱动各层）
- 验收标准：
  - 玩家可在运行时切换至少 1 个部件层（例如头发）
  - 不破坏现有角色动画与碰撞
  - 有至少 1 个渲染回归测试或截图基准

### FND-009（P1）战斗子系统骨架（BattleScene + TurnCore）
- 目标：先把战斗“容器”建立起来，不做完整数值和内容。
- 主要改动：
  - 新建 `BattleScene`（可 push/pop）
  - 新建 `TurnCore`（回合顺序、行动点/速度排序最小实现）
  - 与探索模式的切换协议（进入战斗、战斗结束返回）
- 验收标准：
  - 可从探索模式进入/退出战斗场景
  - 2v2 最小回合流可以跑完（攻击/结束回合）
  - 不影响存档/读档稳定性

### FND-010（P1）特效扩展点 + Effekseer 接口层
- 目标：先打渲染接缝，再接第三方特效库。
- 主要改动：
  - 在渲染管线加入 VFX 提交阶段（Scene 后、UI 前）
  - 抽象 `VfxBackend` 接口，默认空实现
  - 提供 `EffekseerBackend` 草版接入（可编译开关）
- 验收标准：
  - 无 Effekseer 时可正常构建运行
  - 开启 Effekseer 后可播放一个测试特效
  - 不破坏现有光照/UI pass

## 风险与缓解

### R1：重构期间行为回归
- 缓解：
  - 每个 FND 任务都要求回归测试
  - 每日跑 `ctest --test-dir build`

### R2：Lua 接入导致调试困难
- 缓解：
  - 限制首批 API 面积
  - 所有脚本调用入口做统一日志与错误栈输出

### R3：换装导致渲染批次暴涨
- 缓解：
  - 先实现层级功能，再做批处理优化
  - 用 debug 面板追踪 draw call 变化

### R4：Effekseer 接入影响现有管线
- 缓解：
  - 先抽象 `VfxBackend`
  - 开关化集成，默认关闭
