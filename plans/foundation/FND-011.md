## 审阅意见处理结论（2026-02-26）
1. 关于 `VfxPass::flush()` 签名不明确：采纳。  
明确为：`VfxPass::Stats flush(const engine::vfx::VfxRenderContext& context)`。

2. 关于 stats 回传机制：采纳。  
`flush()` 返回 `VfxPass::Stats`，`GLRenderer` 仅消费返回值，不穿透访问 backend。

3. 关于 `enqueue`/`enqueueBatch` 共存：采纳。  
在本任务内直接移除 `enqueue()`，统一为 `enqueueBatch()`，不保留双接口。

4. 关于 `std::span` 标准兼容：采纳。  
项目已启用 `C++20`（`cmake/CompilerSettings.cmake`），可直接使用 `std::span`。

5. 关于 `VfxPass::clean()` 语义：采纳。  
`clean()` 负责置空 backend 非拥有指针并清零内部统计缓存。

6. 关于 `RecordingVfxBackend` 同步改造：采纳。  
将其纳入接口切换原子步骤，与 production backend 一并改造。

7. 关于批次接口收益预期：采纳。  
文档下调性能预期，强调语义边界与扩展性收益，而非短期 FPS 提升。

8. 关于 `RenderPass` 继承层级：采纳。  
`VfxPass` 继承 `RenderPass`（不继承 `ReloadableRenderPass`），因其不管理本地 shader。

9. 关于 viewport 隐式依赖：采纳。  
`VfxPass::flush()` 中显式设置 `glBindFramebuffer(GL_FRAMEBUFFER, 0)` 与 `glViewport(...)`。

10. 关于步骤顺序导致中间编译断裂：采纳。  
接口切换改为原子步骤：`VfxBackend + Null/Effekseer/Recording + VfxService + tests` 同步完成。

## 背景与问题
当前 Effekseer 已接入并可在游戏中显示，但在渲染架构上仍存在两个结构性问题：
1. VFX 渲染调用直接写在 `GLRenderer::present()`，尚未像 `Scene/Lighting/Emissive/Bloom/UI` 一样形成独立 Pass 对象，导致职责边界不清。
2. VFX 请求在 service 层逐条 `enqueue` 到 backend，缺少“批次提交”接口，后续做高频技能特效时不利于扩展和优化。

结论：Effekseer 内部已有自身 draw batching 能力，本任务重点不是“立刻提性能”，而是补齐引擎层“Pass 级通道抽象 + 批次提交语义边界”，为后续扩展打地基。

## 目标
- 在 `src/engine/render/opengl` 中为 VFX 增加独立 `VfxPass`，统一到现有 Pass 管线风格。
- 将 `GLRenderer` 对 VFX 的直接渲染调用下沉到 `VfxPass`，降低耦合。
- 为 `VfxBackend` 增加批次提交能力（一次 update 提交一批请求），建立后续优化扩展点。
- 保持当前可见行为与渲染顺序：`Composite -> VFX -> UI`。

## 非目标
- 不在本任务中引入“pre-composite world-vfx FBO”路径。
- 不重写 Effekseer 内部渲染逻辑（继续使用官方 manager/renderer 流程）。
- 不做战斗技能特效内容层接入（只做架构层改造）。

## 方案备选
### 方案A：仅在 `GLRenderer` 内保留直接调用（最小改动）
- 优点：改动最小，风险最低。
- 缺点：仍无独立 Pass，后续扩展继续堆在 `GLRenderer`，不可取。

### 方案B：新增 `VfxPass` + backend 批次接口（推荐）
- 优点：与现有 Pass 架构一致，职责清晰；同时补齐批次提交边界，后续可继续演进到 world/overlay 双通道。
- 缺点：需要调整 `GLRenderer` 与 `VfxBackend` 接口，并更新相关测试。

### 方案C：一次性改为 world-vfx FBO + overlay-vfx 双通道
- 优点：架构最完整。
- 缺点：一次性改动过大，且 Effekseer 混合模式在离屏合成路径下需要额外验证，当前阶段风险偏高。

## 方案结论
采用 **方案B**：先完成“VFX 独立 Pass + 批次提交接口”重构，保持现有视觉行为稳定；将 world-vfx FBO 作为后续独立任务推进。

## 实现思路（最优方案）
1. **新增 `VfxPass`（OpenGL 渲染层）**
- 新建 `engine/render/opengl/vfx_pass.h/.cpp`，继承 `RenderPass`。
- 选择 `RenderPass`（非 `ReloadableRenderPass`），因为 `VfxPass` 不管理 shader 热重载。
- `VfxPass` 持有 `VfxBackend*` 非拥有指针，通过 `setBackend()` 注入。
- 明确接口：
  - `void setBackend(engine::vfx::VfxBackend* backend);`
  - `VfxPass::Stats flush(const engine::vfx::VfxRenderContext& context);`
  - `void clean() override;`
- `flush()` 明确执行：
  - `glBindFramebuffer(GL_FRAMEBUFFER, 0)`
  - `glViewport(context.viewport_pixels...)`
  - 调用 backend `render(context)`
  - 返回 `Stats{draw_calls, instance_count}`

2. **收口 `GLRenderer` 的 VFX 职责**
- `GLRenderer` 新增 `std::unique_ptr<VfxPass> vfx_pass_`。
- `init()` / `createHeadless()` 中直接创建 `vfx_pass_`，`clean()` 统一释放 `vfx_pass_`。
- `present()` 中改为调用 `const auto stats = vfx_pass_->flush(vfx_context)`，不再直接操作 backend。
- `GLRenderer::pass_stats_[PassType::Vfx]` 由 `flush()` 返回值填充（`draw_calls` / `sprite_count=instance_count`）。
- `setVfxBackend()` 委托 `vfx_pass_->setBackend(...)`，`GLRenderer` 不再穿透管理 backend render 细节。

3. **补齐 service -> backend 的批次提交边界**
- `VfxBackend` 接口切换为：
  - `enqueueBatch(std::span<const VfxPlayRequest> requests)`
  - `update(float dt)`
  - `render(const VfxRenderContext& context)`
  - stats 访问器
- 移除旧 `enqueue()`，不做双接口并存。
- `VfxService::update()` 改为“单帧一次批量提交 + 一次 update”。
- 该改造以“语义清晰、扩展友好”为首要目标，性能收益视后续 profile 决定。

4. **EffekseerBackend 批次适配**
- `enqueueBatch(...)` 内进行一次性遍历，避免高频虚调用。
- 批次前预留 `active_handles_` 容量，减少 burst 场景反复扩容。
- 保持 `manager_->Draw(...)` 单次提交，继续利用 Effekseer 内部 batching。
- 同步改造 `NullVfxBackend` 与 `tests/shared/recording_vfx_backend.h`。

5. **测试与可观测性同步**
- 更新 `render_pass_interface_test`：`VfxPass` 必须继承 `RenderPass`。
- 更新 `vfx_pipeline_stage_test`：验证 `present()` 通过 `vfx_pass_->flush()` 执行并保持顺序 `Composite -> VFX -> UI`。
- 扩展 `vfx_service_test`：验证“单帧一次 enqueueBatch 调用 + 正确请求内容”。
- `GLRendererDebugPanel` 的 `PassStats::Vfx` 继续可见，确保调试链路不回退。

## 风险与缓解
- 风险：批次接口改动导致现有测试桩和 backend 接口不一致。
- 缓解：采用“接口原子切换”步骤，同步改 `VfxBackend + VfxService + Null/Effekseer/Recording + tests`，避免中间态断编译。

- 风险：Pass 化后 GL 状态边界变化导致 UI 渲染被污染。
- 缓解：`VfxPass` 内保持最小状态改动，依赖 Effekseer 状态恢复并补充回归测试。
