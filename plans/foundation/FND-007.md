## 目标
- 将脚本运行时收口为“白名单 API + 只读入口”，并显式封堵危险全局函数，避免脚本侧越权访问宿主能力。
- 建立统一脚本实体句柄（非裸 `entity id`）与两层校验流程，阻断失效对象访问。
- 明确并实现场景切换时的脚本上下文回收策略，避免跨场景悬垂引用与事件残留。
- 增加轻量脚本执行上限保护，防止死循环脚本阻塞主线程。

## 范围
- 重构 `ScriptHost` 初始化安全策略（白名单库、危险全局函数封堵、只读命名空间、错误语义统一）。
- 重构 `script_bindings` 的实体参数形态（从原始 `uint32_t` 切到脚本句柄 usertype）。
- 引入“脚本会话 token + 句柄校验”机制，覆盖 command/dialogue 入口。
- 引入 Lua 指令计数 hook（`lua_sethook`）做执行上限保护。
- 在 `GameScene` 清理流程显式回收脚本上下文，并清理脚本相关队列事件。
- 补齐安全边界测试（危险函数封堵、只读表、失效句柄、死循环保护）。
- 文档更新：补充脚本 API 安全约束与生命周期约定。

## 非目标
- 不引入 OS 级沙箱（进程隔离、seccomp、文件系统虚拟化等）。
- 不实现脚本协程调度器/定时器系统（仅做当前同步调用链的安全收口与指令上限保护）。
- 不做大规模剧情脚本迁移（仅调整宿主层契约与现有测试脚本）。

## 当前基线
- `src/game/script/script_host.cpp` 当前开启 `base/math/table/string/package` 标准库，`package` 暴露范围偏大。
- `src/game/script/script_host.cpp` 当前未封堵 `base` 库中的 `dofile/loadfile/load`，脚本仍可加载任意 Lua chunk。
- `src/game/script/script_bindings.cpp` 当前主要以 `std::uint32_t -> entt::entity` 方式接收脚本目标实体，无场景代际校验。
- `src/game/script/script_bindings.cpp` 的 `resolveTargetEntity(...)` 仅做当前 `registry.valid(...)` 检查，缺少统一句柄语义。
- `src/game/script/script_bindings.cpp` 当前 `tf.command.*` 使用 `dispatcher.trigger()`（同步），`tf.dialogue.*` 使用 `dispatcher.enqueue()`（异步）。
- `src/game/runtime/game_runtime_assembler.cpp` 已在启动时创建 `ScriptHost` 并尝试执行 `scripts/bootstrap.lua`，但未定义独立 shutdown 协议。
- `src/game/scene/game_scene.cpp` 当前 `clean()` 未显式执行脚本宿主回收；`Scene::clean()` 会重置 `registry_`，生命周期边界不够直观。
- `src/engine/core/context.h` 中 dispatcher 为 Context 级全局引用，不随 `Scene::clean()` 重置；已排队事件可能跨场景生存。
- 现有测试仅覆盖 smoke/command bridge（`tests/game/script_host_smoke_test.cpp`、`tests/game/script_host_command_bridge_test.cpp`），尚无“失效句柄/跨场景失效”测试。

## 实现思路（最优方案）
1. **脚本环境最小权限化（Whitelist by default）**
- `ScriptHost::init()` 仅开启必要标准库：`base/math/table/string`。
- 去除 `package` 默认暴露，避免脚本侧任意 `require/loadlib` 扩展。
- 显式封堵危险全局函数：`dofile`、`loadfile`、`load`（可选同时封堵 `string.dump`）。
- 固定导出只读 `tf` 命名空间并冻结子表（`tf.time/tf.player/tf.command/tf.dialogue`），禁止脚本改写宿主 API 表结构。

2. **引入轻量执行配额保护**
- 在 `ScriptHost::init()` 中通过 `lua_sethook(..., LUA_MASKCOUNT, N)` 设置指令上限。
- 超限时返回脚本错误并记录日志，保证主循环继续运行（soft-failure）。

3. **引入统一 `ScriptEntityHandle`（替代裸 ID）**
- 新增脚本句柄结构：`entity + scene_token`（必要时补充 `debug_label` 仅用于日志）。
- 句柄通过 Sol2 usertype 暴露，避免 plain table 易伪造问题。
- 仅允许通过受控 API 获取句柄（如 `tf.player.handle()`）；命令与对话 API 统一接收可选句柄。
- 旧版“直接传 `uint32_t entity id`”路径移除（本任务不考虑向后兼容）。

4. **建立句柄校验与失效拦截通道**
- 在 `ScriptHost` 内维护当前会话 `scene_token`，并提供统一 `validateHandle(...)`。
- 两层校验语义（需写入头文件注释并在代码中显式实现）：
  - `scene_token`：跨场景代际校验（防止旧场景句柄在新场景误用）。
  - `entt::entity`（含 version）+ `registry.valid(entity)`：同场景内有效性校验（防 ABA）。
- 失败时仅返回 `false` + `warn` 日志，不抛异常、不崩溃。
- `tf.command.*`、`tf.dialogue.*` 统一走该校验入口。

5. **场景切换生命周期显式回收**
- 新增 `ScriptHost::shutdown()`：清理 Lua 状态、失效化会话 token、标记 not-ready。
- `shutdown()` 明确幂等：允许重复调用，不产生副作用。
- `GameScene::clean()` 在 `Scene::clean()` 前先执行 `script_host->shutdown()` 并 `reset()`。
- 在 `GameScene::clean()` 中补充脚本相关队列事件清理：`dispatcher.clear<game::defs::DialogueShowEvent>()`、`dispatcher.clear<game::defs::DialogueHideEvent>()`（防跨场景残留）。
- 保证“场景退出后任何旧句柄调用”必然被安全拦截。

6. **测试先行锁定安全契约**
- 先写安全测试骨架（红），再逐步实现（绿）。
- 新增安全边界测试（危险函数封堵、只读命名空间、句柄失效、跨场景失效、指令上限）。
- 更新现有脚本测试以适配新句柄 API。
- `ENABLE_SCRIPTING=ON` 配置下执行定向测试与全量回归。

## 验收标准（DoD）
- 脚本侧只暴露白名单 API，不可直接访问宿主原始注册表能力。
- `dofile/loadfile/load`（及选定的其他危险函数）被显式封堵，并有测试覆盖。
- `tf` 顶层与子表均不可被脚本写入覆盖。
- 脚本实体访问统一走句柄校验通道，明确区分 `scene_token`（跨场景）与 EnTT version（同场景）两层语义。
- 场景切换后旧脚本句柄必定失效，且无崩溃、无裸指针悬挂。
- 死循环脚本可被指令上限中断，主循环不中断。
- `ENABLE_SCRIPTING=ON` 下新增测试通过，且关键回归通过。

## 风险与回滚
- 风险：
  - API 破坏性调整会导致现有脚本样例失效。
  - 白名单收紧后，部分脚本调试手段可能受限。
  - 指令上限阈值过低会误杀合法脚本，过高则防护效果下降。
  - 场景清理时清空对话队列可能丢弃本帧尾部消息（可接受取舍）。
  - 生命周期钩子接线遗漏会造成“看似回收、实则可调用”的隐性问题。
- 缓解：
  - 测试先锁定新契约，再迁移测试脚本。
  - 保留统一 warn 日志，便于快速定位被拦截调用。
  - 指令阈值先采用保守默认值，并通过回归测试校准。
  - `GameScene::clean()` 与 `ScriptHost::shutdown()` 双侧都做幂等保护。
- 回滚策略：
  - 若回归风险过高，先保留 `shutdown` 生命周期回收与句柄校验，再按优先级回退“只读表冻结/指令上限”等增强项。
