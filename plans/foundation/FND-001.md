## 目标
- 将 `GameScene` 从“大型装配器 + 运行编排器”拆分为“场景生命周期 + 轻量编排”，把装配逻辑下沉到独立 runtime 模块，降低后续 FND-002/FND-003/FND-006 改造成本。

## 范围
- 拆分 `GameScene` 内以下职责：
  - 系统创建与依赖注入
  - 基础服务装配（factory/map/save 的装配入口）
  - 场景启动期初始化流水线中可提取的纯装配步骤
- 新建 `game/runtime/` 下的装配模块（命名可微调，但职责必须稳定）。
- 保持外部行为不变（场景切换、输入、UI、存档读写入口）。

## 非目标
- 不改系统执行顺序语义（该项属于 `FND-002`）。
- 不改事件模型（该项属于 `FND-003`）。
- 不引入 Lua/Sol2 或新玩法系统（该项属于后续任务）。

## 当前基线
- 代码现状：
  - `src/game/scene/game_scene.cpp:112` `GameScene::init()` 承担大量初始化流程。
  - `src/game/scene/game_scene.cpp:400` `initSystems()` 包含绝大部分系统构造与注入。
  - `src/game/scene/game_scene.cpp:544` `initUI()` 与装配期状态耦合较重。
  - `src/game/scene/game_scene.cpp:179` `update()` 体现顺序依赖，暂不改语义。
- 体量现状：
  - `src/game/scene/game_scene.cpp` 当前约 `736` 行。
- 测试现状：
  - `ctest --test-dir build --output-on-failure -j4` 当前基线 `126/126` 通过（3 skip）。

## 方案与决策
- 方案摘要：
  - 新增 runtime 装配层，负责创建系统对象和关键服务对象。
  - `GameScene` 保留：
    - 生命周期函数（`init/update/render/clean`）
    - 极少量场景级输入与 UI 回调绑定
    - 调用 runtime 装配产物的入口
  - 装配层输出结构化结果（系统集合/服务句柄），由 `GameScene` 持有并驱动。
- 建议目录（可按实现调整）：
  - `src/game/runtime/game_runtime_assembler.h/.cpp`
  - `src/game/runtime/system_bundle.h`（或等价结构）
- 备选方案（放弃）：
  - 继续在 `GameScene` 内按函数分块，不引入新模块。
  - 放弃原因：函数分块无法解决跨阶段依赖耦合，后续任务仍需反复改 `GameScene`。
