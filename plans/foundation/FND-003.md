## 目标
- 明确区分“意图输入（Command）”与“业务结果（DomainEvent）”，降低 UI/输入层与业务系统的直接耦合。
- 在不回退现有行为的前提下，完成高频链路 `Inventory / Hotbar / Interact / UseItem` 的边界收口。
- 统一命名语义：本次范围内 `*Request` 统一迁移为 `*Command`，结果通知保持 DomainEvent 语义并最小化改名。

## 范围
- 新增命令定义文件 `game/defs/commands.h`，承载本次范围内的用户意图命令。
- 采用最小拆分策略：新增 `commands.h`，`events.h` 保持承载既有 DomainEvent 与范围外事件，不引入 `domain_events.h`。
- 改造以下链路为“输入/UI -> Command -> 系统处理 -> DomainEvent”：
  - 物品栏：移动、分页、同步、使用物品入口
  - 快捷栏：绑定/解绑/激活/同步
  - 交互：仅交互意图命令化，保持现有多订阅者扇出模式
  - 使用物品：消耗与产出效果
- 补齐跨系统库存命令链路：`FarmSystem / PickupSystem / ChestSystem` 发出的 `AddItemRequest` 同步迁移为 `AddItemCommand`。
- 更新对应测试与回归测试。

## 非目标
- 不改调度框架（`SystemScheduler`）与 mode 机制（`FND-002` 范围）。
- 不改存档 schema、Lua 接入或战斗系统。
- 不重构非本次链路的事件（例如 `AdvanceTimeRequest`、`ToggleLightRequest` 等）；
  仅在必要处做最小一致性修正。
- 不在本次重命名既有 DomainEvent（例如 `InventoryChanged`、`HotbarChanged`）。

## 实现思路（最优方案）
- 采用“直接切换”策略，不做兼容桥接层：
  - UI/输入/调试层只发 `Command`
  - 业务系统不再订阅 UI 请求结构体
  - 业务系统处理后只发 `DomainEvent`
- 使用现有 `entt::dispatcher`，不引入新总线，避免额外运行时复杂度。
- 明确调度策略，避免行为漂移：
  - 保持当前交互手感与链式处理：本次范围内命令链路默认使用 `trigger()`
  - 仅在明确需要延迟/异步语义时使用 `enqueue()`（如场景初始化、动画触发等既有路径）
  - 不在 FND-003 引入“DomainEvent 一律 enqueue”规则，避免 UI/系统回归
- 命令分层（本次范围）：
  - InventoryCommand：`Move/SetPage/Sync/Add/Remove/Use`
  - HotbarCommand：`Bind/Unbind/Activate/Sync`
  - InteractionCommand：`InteractCommand`（意图）
- 交互链路采用“仅命令化”最小改造：
  - `InteractRequest -> InteractCommand`
  - `InteractionSystem` 继续只负责选目标并发布交互意图
  - `Dialogue/Chest/Rest` 继续作为订阅者按组件语义各自处理（保留扩展点）
- `ItemUse` 链路改造为：
  - `UseItemCommand` -> `ItemUseSystem`
  - `ItemUseSystem` 产出库存变更命令（`Add/Remove`）
  - `InventorySystem` 发出库存结果事件（沿用既有 `InventoryChanged`）
- 命名规范统一：
  - `*Request` 改为 `*Command`（输入意图）
  - 结果通知统一按 DomainEvent 语义使用，既有事件名保持不变（如 `InventoryChanged` / `HotbarChanged`）

## 风险与回滚
- 风险：
  - 命名批量迁移导致编译期连锁错误。
  - `ItemUse` 与 `Inventory/Hotbar` 链路交叉迁移时出现中间不可编译状态。
  - `trigger/enqueue` 语义未统一导致行为差异（即时 vs 延迟）。
- 缓解：
  - 先完成定义层，再按“Inventory/Hotbar/ItemUse 一体迁移”推进，确保每步可编译。
  - 对交互链路保持最小改造（只命令化不加中间解析事件），避免过度设计回归。
  - 对关键路径显式约定 `trigger/enqueue` 策略并用测试覆盖事件流。
- 回滚策略：
  - 按步骤小提交；回归时仅回退最近一条链路迁移（Inventory/Hotbar/Interact/UseItem）。
