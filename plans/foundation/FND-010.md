## 审阅意见处理结论（2026-02-25）
1. 关于 VFX 阶段位置：采纳。  
本任务明确为 **Phase 1: post-composite**，并在文档中补充 **Phase 2: pre-composite world VFX 层** 路线，避免后续战斗技能特效“悬浮感”。

2. 关于生命周期归属：采纳。  
`VfxService` 归 `GameRuntimeServices` 持有；`VfxService` 内持有 `VfxBackend`；`GLRenderer` 只持有 `VfxBackend*` 非拥有指针。

3. 关于 `PassType` 顺序：采纳。  
新增 `PassType::Vfx` 并明确插入在 `Bloom` 与 `UI` 之间。

4. 关于 2D/3D 坐标映射：采纳。  
补充明确约定：正交投影、`XY` 对应逻辑世界坐标（1 unit = 1 像素）、`Z` 默认 `0`。

5. 关于 GL 状态恢复：采纳。  
首选 `SetRestorationOfStatesFlag(true)`，并增加回归验证；若不足再补手动恢复兜底。

6. 关于 CMake 接入细化：采纳。  
补充关闭选项清单，收敛为仅使用 `Effekseer` + `EffekseerRendererGL`。

7. 关于测试资源来源：采纳。  
使用你已放入的官方样例目录 `assets/vfx/00_Basic`，不再新增 `assets/vfx/debug/Laser01.efkefc`。

## 目标
- 在现有 OpenGL 渲染管线中增加独立 VFX 阶段（Phase 1 先落在 `Composite` 后、`UI` 前）。
- 建立 `VfxBackend` 抽象层，默认 `NullVfxBackend`，保证无 Effekseer 时构建/运行不回退。
- 开启 Effekseer 后通过调试入口播放官方样例特效（来自 `assets/vfx/00_Basic`）。

## 非目标
- 不做完整粒子编辑器工作流（`.efkproj` 编辑与导出流程后置）。
- 不做战斗技能特效批量接入（先打通引擎接缝与最小调用链）。
- 不做特效资产管理平台化（先使用最小 catalog + debug 触发）。

## Phase 边界与后续路线
- Phase 1（本任务）：`post-composite` VFX  
优点：接入成本低、风险可控。  
限制：VFX 不参与现有光照/发光/泛光合成。

- Phase 2（后续任务）：`pre-composite` world VFX pass  
新增 world-vfx FBO 并接入 composite 输入，区分 world-space VFX 与 screen-space overlay VFX。

## 当前实现缺口
- 渲染流程当前为 `Scene -> Lighting -> Emissive -> Bloom -> Composite -> UI -> ImGui`，没有 VFX 专属阶段。
- 引擎层没有统一的特效后端抽象，第三方特效库无法按开关接入。
- 游戏侧没有 `PlayVfx` 语义命令，也没有从玩法事件到特效播放的桥接层。

## 方案结论
- 采用 `VfxBackend` 抽象 + `Null/Effekseer` 双后端方案。  
- 先完成骨架可运行，再在后续任务扩展 pre-composite world VFX。

## 实现思路（最优方案）
1. **生命周期与所有权链（修订）**
   - `GameRuntimeServices` 持有 `std::unique_ptr<VfxService>`。
   - `VfxService` 持有 `std::unique_ptr<VfxBackend>`。
   - `GLRenderer` 持有 `VfxBackend*`（non-owning，仅渲染阶段调用）。
   - `GameRuntimeAssembler` 负责绑定：创建 service 后将 backend 指针注入 `GLRenderer`；`GameScene::clean()` 解绑为 `nullptr`。

2. **渲染管线插入 VFX 阶段**
   - 在 `GLRenderer::present()` 中插入 VFX 调用，顺序固定：
   - `Scene -> Lighting -> Emissive -> Bloom -> Composite -> VFX -> UI -> ImGui`
   - `PassType` 明确调整为：
   - `Scene, Lighting, Emissive, Bloom, Vfx, UI, Count`

3. **引擎层新增后端抽象**
   - 新增 `engine::vfx::VfxBackend` 接口与 `NullVfxBackend` 默认实现。
   - `GLRenderer` 只依赖 `VfxBackend` 抽象，不包含 Effekseer 头文件。

4. **Effekseer 后端最小接入**
   - `ENABLE_EFFEKSEER=ON` 时启用 `EffekseerBackend`。
   - 初始化 `EffekseerRendererGL::Renderer` 与 `Effekseer::Manager`。
   - 配置 renderer/model/texture/material/curve loader。
   - 每帧 `Manager::Update` + `Manager::Draw`。
   - 首选 `SetRestorationOfStatesFlag(true)` 控制 GL 状态恢复。

5. **2D 坐标映射约定（补充）**
   - 投影：正交投影。
   - 坐标：游戏逻辑坐标 `XY` 与 Effekseer 世界坐标 `XY` 一一对应（1 unit = 1 像素）。
   - 深度：首版固定 `Z=0`（后续如需层次可扩展 `z_bias`）。
   - 矩阵：以当前 camera 的视图/投影参数同步到 Effekseer（避免坐标系漂移）。

6. **游戏侧触发链路**
   - 新增 `PlayVfxCommand`（command 语义）。
   - 新增 `VfxBridgeSystem`：监听命令并提交到 `VfxService`。
   - `PlayerDebugPanel` 新增调试按钮触发测试特效。

7. **最小数据化与资源来源**
   - 新增 `assets/data/vfx_catalog.json`。
   - 测试特效直接使用官方样例资源目录：`assets/vfx/00_Basic`。

8. **构建策略细化（补充）**
   - 新增 `ENABLE_EFFEKSEER`（默认 `OFF`）。
   - `OFF`：仅构建 `NullVfxBackend`。
   - `ON`：加载 `EffekseerDependencies.cmake`，关闭无关子模块，仅接入 `Effekseer` + `EffekseerRendererGL`。

## CMake 约束（Effekseer）
- 关闭项（至少）：`BUILD_VIEWER=OFF`、`BUILD_EDITOR=OFF`、`BUILD_TEST=OFF`、`BUILD_EXAMPLES=OFF`、`BUILD_UNITYPLUGIN=OFF`、`BUILD_UNITYPLUGIN_FOR_IOS=OFF`。
- 图形后端：`BUILD_GL=ON`，其余 `BUILD_VULKAN/DX9/DX11/DX12/METAL=OFF`。
- 音频相关（避免无关目标）：`USE_OPENAL=OFF`、`USE_XAUDIO2=OFF`、`USE_DSOUND=OFF`、`USE_OSM=OFF`。
- 可选：`NETWORK_ENABLED=OFF`（首版不需要网络模块）。

## 风险与缓解
- 风险：Effekseer 改写 OpenGL 状态影响 UI pass。  
缓解：优先启用 `SetRestorationOfStatesFlag(true)`，并增加 UI 回归校验；不足时再补手动恢复兜底。

- 风险：第三方 CMake 子项目引入无关目标导致构建不稳定。  
缓解：在依赖模块中显式关闭 viewer/examples/test/sound/其他图形后端，并只链接 `Effekseer` 与 `EffekseerRendererGL`。

- 风险：2D/3D 坐标映射不一致导致特效偏移。  
缓解：固定正交投影与 `XY 1:1` 约定，增加播放位置回归测试。
