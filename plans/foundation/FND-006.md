## 目标
- 引入可开关脚本宿主层（`ENABLE_SCRIPTING`），保证脚本加载/执行可用且报错不崩溃主循环。
- 完成 Lua + Sol2 的 CMake 接入，满足“本地源码优先、缺失自动下载”。
- 提供最小脚本 API（读时间、读玩家、发 command、弹文本），跑通至少 1 条脚本驱动链路。

## 范围
- 顶层 CMake 新增 `ENABLE_SCRIPTING` 开关，并定义 `TF_ENABLE_SCRIPTING`。
- 脚本依赖版本（来自 `plans/tmp/note.md`）：
  - Lua：`https://github.com/lua/lua` + `v5.4.8`
  - Sol2：`https://github.com/ThePhD/sol2` + `v3.5.0`（该 tag 的工程版本为 `4.0.0`，按 tag 作为锁定版本）
- 依赖来源策略：
  - 优先本地源码：`external/lua-5.4.8`、`external/sol2-3.5.0`
  - 本地缺失时自动 FetchContent 下载同版本
- 新建 `ScriptHost` 与绑定层，并接入 runtime 装配。

## 非目标
- 不做大规模剧情脚本迁移（`DialogueSystem` 当前 JSON 管线保持不变）。
- 不实现完整脚本安全边界（白名单强化/句柄校验留给 `FND-007`）。
- 不改 `SystemScheduler` 阶段模型，仅做最小接入点。

## 当前基线
- `CMakeLists.txt:20` 当前无 `ENABLE_SCRIPTING`，仅有 `BUILD_SHARED_LIBS` 与 `ENABLE_DEBUG_UI`（另有 `BUILD_TOOLS`、`BUILD_TESTING`）。
- `cmake/Dependencies.cmake:233` 依赖入口当前不含 Lua/Sol2。
- `external/lua-*` 上游为 Makefile 工程（无 CMakeLists），不能直接复用 `find_or_fetch_dependency` 的 `add_subdirectory` 路径。
- `external/sol2-3.5.0/CMakeLists.txt:25` 要求 `cmake_minimum_required(VERSION 3.26.0)`，与本项目 `CMakeLists.txt:4` 的 `3.13.0` 不兼容。
- `src/game/runtime/system_bundle.h:36` 当前 runtime services 不含脚本宿主对象。

## 实现思路（最优方案）
1. `ENABLE_SCRIPTING` 作为总开关，关闭时零侵入。  
说明：`OFF` 时不链接 Lua/Sol2、不编译脚本源文件；`ON` 时才开启脚本路径。
2. Lua 与 Sol2 都采用“自定义依赖逻辑”，不走通用宏。  
说明：`find_or_fetch_dependency` 依赖 `add_subdirectory`，不适配 Lua（无 CMake）且不适配 Sol2（CMake 3.26 门槛）。
3. Sol2 统一手动 INTERFACE target。  
说明：无论本地/下载来源，统一 `sol2::sol2` 指向 include 目录，不调用 Sol2 上游 CMake。
4. Lua 统一手动静态库 target。  
说明：对 `lua` 源码目录 `*.c` 构建静态库并排除 `lua.c`/`luac.c`（避免 main 符号冲突），统一别名为 `Lua::Lua`。
5. `ScriptHost` 采用 runtime service 接入 + 初始化软失败。  
说明：初始化失败只 `warn` 并禁用脚本功能，不阻断 `GameScene` 启动。

## 风险与回滚
- 风险：
  - Sol2 tag 与其 project version 命名不一致，后续排障易混淆。
  - Lua 上游无 CMake，FetchContent 后仍需手动构建目标。
  - 脚本接线若做成硬失败会放大初始化失败范围。
- 缓解：
  - 在文档和日志统一记录：`sol2 tag v3.5.0 (project version 4.0.0)`。
  - Lua/Sol2 均使用本项目归一 target，避免来源差异外溢。
  - ScriptHost 采用软失败策略，脚本功能失败不阻断主流程。
- 回滚策略：
  - 若回归，优先回退 ScriptHost 运行时接线；保留依赖与测试资产。
