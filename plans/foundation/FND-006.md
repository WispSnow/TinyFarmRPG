## 目标
- 引入可开关的脚本宿主层（`ENABLE_SCRIPTING`），在不影响现有主流程的前提下让 Lua 脚本可加载、可执行、可报错不崩溃。
- 完成 Lua + Sol2 的 CMake 接入，满足“本地源码优先、缺失时自动下载”的依赖策略。
- 提供最小脚本 API：读时间、读玩家、发 command、弹文本，并跑通至少 1 条脚本驱动链路。

## 范围
- CMake 侧新增 `ENABLE_SCRIPTING` 开关与脚本依赖装配逻辑。
- 依赖来源策略：
  - 优先使用本地源码：`external/lua-5.5.0`、`external/sol2-3.5.0`
  - 本地缺失时自动 FetchContent 下载（版本固定）：
    - Lua：`https://github.com/lua/lua` + `v5.5.0`（来自 `plans/tmp/note.md`）
    - Sol2：`https://github.com/ThePhD/sol2` + `v3.5.0`（来自 `plans/tmp/note.md`）
- 新建 `ScriptHost`（加载/执行/错误处理/热重载入口）。
- 在 runtime 装配层接入 `ScriptHost`，并提供一个最小脚本示例链路。

## 实现思路（最优方案）
1. 采用“可选开关 + 双来源依赖”的接入策略。  
说明：`ENABLE_SCRIPTING=OFF` 时完全不引入 Lua/Sol2 依赖；`ON` 时按“本地源码优先，缺失自动下载”装配。
2. Lua 与 Sol2 采用分层接入，避免构建耦合。  
说明：Sol2 作为 header-only 接口目标（`sol2::sol2`）；Lua 统一归一为 `Lua::Lua`，优先 `find_package(Lua)`，否则走 vendored Lua 静态库构建（或下载后构建）。
3. `ScriptHost` 作为 runtime service 挂载，不污染系统调度主链。  
说明：保持 `SystemScheduler` 现有阶段不变，脚本执行入口先放在明确调用点（初始化 smoke 或显式调用），避免隐式顺序耦合。
4. 错误处理统一收口到 `ScriptHost`。  
说明：脚本加载/运行错误仅记日志并返回失败，不向主循环抛异常。

## 验收标准（DoD）
- `ENABLE_SCRIPTING=OFF` 时不引入 Lua/Sol2 依赖，现有行为与测试基线不回退。
- `ENABLE_SCRIPTING=ON` 时 Lua/Sol2 可成功接入，且满足：
  - 本地源码存在时优先使用 `external/lua-5.5.0`、`external/sol2-3.5.0`
  - 本地源码缺失时自动按固定 URL/Tag 下载并构建
- `ScriptHost` 能加载并执行至少一个脚本文件。
- 脚本报错只记录日志，不导致主循环崩溃。
- 至少 1 条脚本驱动链路跑通（发 command 或弹文本）。

## 风险与回滚
- 风险：
  - Lua 上游源码无 CMake，直接复用通用宏会失败。
  - Sol2 若走 `add_subdirectory` 可能受其上游 CMake 版本与选项影响。
  - 脚本绑定 API 过宽导致后续安全边界难收口。
- 缓解：
  - Lua 采用项目内统一构建包装（归一 `Lua::Lua` target），不依赖上游 CMake。
  - Sol2 采用 header-only 接入，避免不必要的子项目构建副作用。
  - 首批 API 严格最小化，所有脚本调用路径统一错误处理和日志。
- 回滚策略：
  - 若回归，优先回退 ScriptHost 接线；保留依赖接入与测试资产。
