## 目标
- 将 `GameScene` 中硬编码的系统更新顺序，收口为可声明、可切换的 `SystemScheduler`。
- 引入 `GameMode`（`Exploration / Battle / PauseOverlay / Cutscene`）作为调度入口，保证后续战斗场景和剧情模式接入时不再改动核心更新链。
- 在不回退当前探索玩法行为的前提下，显式化“切图过渡时冻结逻辑”的规则（含 transition 前后两次 gate 检查语义）。

## 范围
- 新增 runtime 调度模块：`GameMode` + `SystemScheduler`。
- 将 `src/game/scene/game_scene.cpp` 当前 `update()` 中的系统调用序列迁移到 scheduler。
- 在 `GameScene` 提供统一的 mode 切换入口（即使 `Battle` 仍是占位模式）。
- 补充顺序相关测试，至少覆盖：
  - `movement -> spatial_index`
  - `time -> day_night/light`
  - `remove_entity` 在所有 mode 下最先执行

## 非目标
- 不实现完整 `Battle` 玩法流程（仅提供 mode 和调度骨架）。
- 不改动 Command/DomainEvent 边界（该项属于 `FND-003`）。
- `SystemScheduler` 仅负责 `update()` 阶段；不改动渲染管线的大阶段结构（`render()` 仍保持现有主流程）。

## 当前基线
- `src/game/scene/game_scene.cpp:164` 的 `GameScene::update()` 直接硬编码系统更新顺序和分支。
- `src/game/scene/game_scene.cpp:175`、`src/game/scene/game_scene.cpp:199` 通过 `MapTransitionSystem` 分支实现过渡冻结。
- `update()` 当前存在两个关键 gate：
  - gate1：帧开始时 transition 已激活，直接走 `transition + light_toggle`，跳过 gameplay。
  - gate2：执行 gameplay 与 `transition + light_toggle` 后，本帧新激活 transition，则跳过 post-gameplay 阶段。
- `src/game/scene/game_scene.cpp:165` 的 `abort_to_title_` 路径会直接 `Scene::update()`，不走任何系统调用。
- `src/engine/scene/scene_manager.cpp:31` 已约定“仅更新栈顶场景”，PauseOverlay 当前依赖 SceneStack 冻结底层逻辑。
- 顺序相关保护测试目前较弱，主要是源码字符串检查（`tests/game/game_scene_light_toggle_hook_test.cpp`）。

## 实现思路（最优方案）
- 定义 `GameMode` 枚举并作为调度主键，所有系统执行顺序按 mode profile 显式声明。
- 引入 `SystemScheduler`，内部维护“阶段化步骤列表（stage list）”，每个步骤有稳定的语义名称，避免隐式顺序耦合。
- `Exploration` profile 完全对齐当前行为顺序；`Battle/Cutscene` 先提供最小可运行 profile（占位 + 可扩展）。
- `PauseOverlay` 保留在 `GameMode` 中作为未来“GameScene 内嵌暂停态”预留；当前 Pause 菜单仍由 SceneStack push 实现，不参与本次调度链。
- 将“切图过渡冻结”从 `GameScene` if-else 提升为 scheduler 内显式双 gate：
  - gate1（pre-gameplay）：transition 已激活时，仅执行 `remove_entity + transition + light_toggle` 后返回。
  - gate2（post-transition）：本帧执行 `transition + light_toggle` 后若激活 transition，则跳过 post-gameplay（`spatial/pickup/interaction/camera/animation`）。
- 在 profile 定义层保证 `map_transition` 与 `light_toggle` 成对且相邻，避免实现阶段失配。
- scheduler 步骤统一采用 `std::function<void()>` + lambda 捕获（`registry/delta_time/context`），避免本阶段改系统接口签名。
- `GameScene` 仅保留：
  - `abort_to_title_` 的短路分支（在 scheduler 之前返回）
  - `scheduler.tick(mode, dt, ctx)` 调用
  - mode 切换入口（例如 `setGameMode()`）
  - scene 级 UI 与输入绑定
- 为测试暴露稳定的 profile 描述接口（只读 stage id 列表），使顺序测试不依赖源代码字符串。

## 风险与回滚
- 风险：
  - profile 迁移时遗漏系统，导致隐性行为回退。
  - 过渡 gate 放置错误，导致冻结时仍执行 gameplay 逻辑。
  - `PauseOverlay` 与 SceneStack 职责混用，导致概念和实现偏差。
- 缓解：
  - 先做 `Exploration` 等价迁移，再开启 mode 分支。
  - 以“阶段语义 + 顺序测试”锁定关键依赖链。
  - 在代码与文档中明确：当前 Pause 菜单冻结依赖 SceneStack，`PauseOverlay` mode 仅作预留。
- 回滚策略：
  - 按步骤小提交；若回归，回退最近一次 profile 迁移并保留测试资产。
