## 审阅意见处理结论（2026-02-26）
1. **EffekseerBackend 通道划分策略**：采纳审阅建议。  
主方案改为“单 `Manager` + `SetLayer(handle)` + `DrawParameter::CameraCullingMask` 分通道绘制”；不再默认双 manager。

2. **增加 API 可行性验证步骤**：采纳。  
新增 `T0.5` spike：先验证 layer/culling mask 方案可稳定过滤通道，再推进后续实现。

3. **Composite alpha 语义不预设**：采纳。  
新增 `T2.5` spike：实测 world-vfx FBO 的 `rgb/alpha` 输出语义后再锁定融合公式；计划中不再先验写死 premultiplied。

4. **PassType 拆分影响范围**：采纳。  
在 `T4.1` 明确全局替换 `PassType::Vfx` 引用点（renderer debug panel / vfx debug panel / tests）。

5. **World-VFX clear 时机**：采纳。  
明确在 `GLRenderer::clear()` 统一清理 world-vfx FBO，与 scene/light/emissive 一致。

6. **首版 bloom 关系说明**：采纳。  
明确首版 `WorldVfx` 位于 `Bloom` 之后，不参与 bloom；后续可扩展 bloom 采样 world-vfx。

7. **channel 默认值**：采纳。  
`VfxPlayRequest.channel` 默认改为 `Overlay`，保证现有行为不回退；显式标注 `World` 才进入新路径。

## 背景与问题
当前渲染路径为：`Scene -> Lighting -> Emissive -> Bloom -> Composite -> VFX -> UI`。  
VFX 仅有一个 post-composite 通道，导致：
1. world 特效与 overlay 特效没有语义隔离，后续玩法扩展（技能落地特效 vs 屏幕提示特效）会互相牵连；
2. world 特效不在逻辑分辨率离屏层内，后续做更复杂的合成控制（例如与 world 画面统一预览/调试）受限；
3. 调试与统计维度只有单一 `VfxPass`，难以分辨两类问题来源。

## 目标
- 引入方案 C：`World-VFX(FBO)` + `Overlay-VFX(默认帧缓冲)` 双通道。
- world-vfx 进入 composite 输入，成为稳定的 world 合成层。
- overlay-vfx 保持在 composite 之后、UI 之前，用于屏幕层特效。
- 从请求数据到 backend 渲染上下文支持 `channel` 语义。
- 保持既有调用默认行为（post-composite）不变。
- 保持现有非 VFX 渲染行为不回退（Scene/Lighting/Emissive/Bloom/UI）。

## 非目标
- 不在本任务引入新的后处理特效链（色调映射、DOF 等）。
- 不在本任务处理 3D 深度遮挡排序（仍按当前 2D 约定）。
- 不在本任务做特效资源系统平台化改造（catalog 继续最小可用）。

## 方案结论
采用“**新增 `WorldVfxPass` + 保留并语义化现有 `VfxPass` 为 overlay 通道**”的演进方案：  
- world 通道：渲染到逻辑尺寸 FBO，并在 `CompositePass` 内采样融合；  
- overlay 通道：继续渲染到默认帧缓冲 letterbox viewport；  
- backend 通过 `channel` 分流渲染；首选单 manager + layer 过滤。

## 实现思路
1. **VFX 数据契约升级（channel 显式化）**
- 在 `engine::vfx` 增加 `VfxChannel`（`World` / `Overlay`）。
- `VfxPlayRequest` 增加 `channel` 字段（默认 `Overlay`，保持现有行为）。
- `VfxRenderContext` 增加 `channel` 字段，用于 backend 在渲染时切换通道。

2. **新增 `WorldVfxPass`（离屏 FBO）**
- 新建 `world_vfx_pass.h/.cpp`，继承 `RenderPass`。
- 内部管理 `RGBA8` 颜色附件与 FBO（尺寸=logical size）。
- `flush(context)` 调 backend 渲染 world 通道；清屏放在 `GLRenderer::clear()` 统一执行。
- 对外暴露 `getColorTex()` 供 `CompositePass` 采样。

3. **扩展 `CompositePass` 融合 world-vfx（先验证 alpha 契约）**
- 新增 `uWorldVfxTex` 输入与绑定槽位。
- 在实现前用 spike 确认 Effekseer 输出到 world-vfx FBO 的 `rgb/alpha` 语义，再锁定最终公式。
- 首版约束：`World` 通道只承载通过验证的混合模式资源；不满足约束的特效仍走 `Overlay`。
- 无 world-vfx 输入时回退到黑纹理，保持旧行为。

4. **GLRenderer 管线改造为双 VFX 阶段**
- 目标顺序：  
  `Scene -> Lighting -> Emissive -> Bloom -> WorldVfx(FBO) -> Composite -> OverlayVfx(default FB) -> UI -> ImGui`
- `GLRenderer` 新增 `world_vfx_pass_` 生命周期管理。
- `PassType` 拆分为 `WorldVfx` 与 `OverlayVfx` 两项统计。
- `present()` 中分别构造两份 `VfxRenderContext`（`channel=World/Overlay`）并分别 flush。
- 明确：首版 `WorldVfx` 不参与 bloom（位于 bloom 之后）；后续如有需要再扩展 bloom 输入。

5. **EffekseerBackend 双通道路由**
- 基于单 manager：`enqueueBatch()` 时按 `request.channel` 为 handle 设置 layer（如 `0=World, 1=Overlay`）。
- `render(context)` 时通过 `DrawParameter::CameraCullingMask` 仅绘制目标 layer。
- 仅在 `T0.5` 验证失败时，才回退到双 manager 方案（并记录原因）。
- 保留现有“仅针对 Effekseer 的 Y 翻转修正”逻辑，不影响其他渲染路径。

6. **调试面板与测试同步**
- `VfxDebugPanel` 增加 `Spawn Channel`（World/Overlay）切换。
- `GLRendererDebugPanel` 的 PassStats 增加 `WorldVfxPass` 与 `OverlayVfxPass` 行。
- Pass Preview 增加 world-vfx 纹理预览（便于确认 FBO 内容）。

## 分步骤实现
1. **T0：冻结边界与渲染顺序**
- 固化方案 C 的最终顺序，明确 world 与 overlay 的职责边界。

2. **T0.5：Effekseer 通道过滤能力验证（spike）**
- 验证单 manager + `SetLayer` + `CameraCullingMask` 能否稳定实现 world/overlay 分绘制。
- 若验证失败，再评估双 manager 兜底并补充影响说明。

3. **T1：升级 VFX 类型与请求语义**
- 增加 `VfxChannel`，更新 `VfxPlayRequest` / `VfxRenderContext`。
- 更新调用点默认值，保证不标注 channel 时走 `Overlay`。

4. **T2：实现 `WorldVfxPass`**
- 实现 FBO 创建/销毁、透明清屏、flush 与统计输出。
- 在 `GLRenderer::clear()` 中统一清 `WorldVfxPass`（与其他 FBO 一致）。
- 向 `CompositePass` 暴露纹理输入。

5. **T2.5：world-vfx alpha 语义验证（spike）**
- 用至少一组 Alpha Blend 与一组 Additive 资源验证 world-vfx FBO 的 `rgb/alpha` 行为。
- 基于结果确定 composite 公式与 world 通道资源约束。

6. **T3：改造 `CompositePass`**
- 扩展 world-vfx uniform、纹理绑定和最终融合公式（以 `T2.5` 结论为准）。
- 保证 world-vfx 为空时与旧输出一致。

7. **T4：接入 GLRenderer 双通道**
- 新增 `world_vfx_pass_` 生命周期。
- `present()` 中增加 world flush 与 overlay flush 两段。
- 同步 `PassType` 与 pass_stats 采集。

8. **T4.1：全量替换 `PassType::Vfx` 引用点**
- 全局搜索并替换 `PassType::Vfx`，覆盖 renderer/vfx debug panel 与相关测试。

9. **T5：改造 backend/service**
- `enqueueBatch` 按 channel 设置 layer，`render` 按 channel mask 渲染。
- `update()` 保持单 manager 单次更新，不增加双路 update 开销。
- `NullVfxBackend` 与测试桩同步支持 channel。

10. **T6：调试面板增强**
- VFX 面板支持通道选择、统计区分 world/overlay。
- Renderer 面板增加 world-vfx 预览与双通道统计。

11. **T7：测试与回归**
- 更新/新增顺序测试：`WorldVfx` 在 `Composite` 前，`OverlayVfx` 在 `Composite` 后、`UI` 前。
- 更新 service 测试：验证 channel 透传与分流。
- 回归命令：`Vfx|Renderer|GameScene` 相关测试 + game/visual_tester 手动验证。

## 验收标准（DoD）
- world-vfx 与 overlay-vfx 在渲染链路中可独立观测与统计。
- `Composite` 可稳定融合 world-vfx 纹理，视觉不出现黑底/错位。
- overlay-vfx 仍在 UI 前绘制，且不污染 UI 与 ImGui。
- 不显式指定 channel 的现有调用行为保持与当前版本一致（默认走 overlay）。
- `ENABLE_EFFEKSEER=ON/OFF` 双配置构建通过，相关测试通过。

## 风险与缓解
- 风险：Effekseer layer/culling mask 在当前接入方式下不满足预期隔离。
- 缓解：以 `T0.5` 先验证；若失败再启用双 manager 兜底方案。

- 风险：world-vfx 融合公式与 Effekseer 输出预乘规则不一致导致亮度异常。
- 缓解：以 `T2.5` 实测后锁定公式，并限制 world 通道资源类型直到规则稳定。

- 风险：Pass 顺序调整引发隐式 GL 状态依赖问题。
- 缓解：每个 pass 内显式 `glBindFramebuffer + glViewport`，避免依赖前序状态。

## 疑问与待澄清
- 已决策：首版不新增 `space` 字段；`Overlay` 固定为逻辑屏幕坐标。
