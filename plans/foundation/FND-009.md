## 已确认约束
- 本任务只做“可进入/可退出/可跑通回合”的战斗骨架，不做完整数值、技能、AI、掉落系统。
- 采用**独立 BattleScene**，不把战斗循环塞回 `GameScene` 探索更新链。
- 继续遵循 Command -> DomainEvent 边界（沿用 `FND-003`）。
- 采用最优方案实现，可重构，不考虑向后兼容。

## 目标
- 可从探索场景进入战斗场景，并在战斗结束后返回探索场景。
- 提供可扩展的 `TurnCore`（回合顺序、行动执行、胜负判定）。
- 跑通最小 `2v2` 回合流程（攻击/结束回合），并有测试保障。

## 范围
- 新增 `BattleScene`（UI、输入、回合驱动、结算退出）。
- 新增战斗领域核心（`TurnCore` + `BattleSession` 最小模型）。
- 新增探索 -> 战斗触发协议（先用 debug 命令触发，便于验证）。
- 保证返回探索后主场景状态稳定（不崩溃、不丢上下文）。

## 非目标
- 不实现技能树、状态异常、复杂 AI。
- 不实现完整敌人生成与地图遭遇系统。
- 不实现战斗中的存档/读档中断恢复。

## 实现思路（最优方案）
1. **战斗域核心先行（纯逻辑）**
   - 新建 `TurnCore` 管理回合顺序、当前行动者、回合推进与胜负判定。
   - 新建 `BattleSession` 持有对战双方、HP/速度、动作结果快照，供场景层消费。

2. **场景分层：BattleScene 只编排，不承载业务细节**
   - `BattleScene` 负责输入/UI 和调用 `BattleSession`。
   - 回合逻辑全部委托给 `TurnCore/BattleSession`，避免后续技能系统接入时反复改场景流程。

3. **探索与战斗切换协议（低耦合）**
   - 在 `GameScene` 监听战斗进入命令，`requestPushScene(BattleScene)`。
   - `BattleScene` 结束后通过结果回调/事件通知 `GameScene`，然后 `requestPopScene()` 返回探索。

4. **最小可演示回合流**
   - 参与者固定 `2v2`（玩家方 2、敌方 2）。
   - 行动优先级：速度降序，速度相同时按稳定序号（可测试、可复现）。
   - 动作先支持 `Attack`、`EndTurn` 两种。

5. **调试入口优先**
   - 在 debug 面板增加 `Start Test Battle (2v2)` 入口，先打通链路，再接随机遭遇系统。

## 分步骤实现
1. **定义战斗数据与命令契约**
   - 增加战斗参与者、动作、结果结构；增加进入战斗/提交动作/结算结果事件。

2. **实现 TurnCore（纯逻辑）**
   - 实现出手顺序、行动后推进、死亡跳过、战斗结束判定。

3. **实现 BattleSession（应用层）**
   - 封装“执行动作 -> 更新状态 -> 产出快照事件”的流程，供 UI/Scene 调用。

4. **实现 BattleScene（可推可弹）**
   - 场景内构建最小 UI（当前回合方、血量、Attack/EndTurn 按钮）。

5. **接入 GameScene 过渡逻辑**
   - `GameScene` 增加战斗进入监听与 `requestPushScene`。
   - `BattleScene` 结束时通知并 `requestPopScene`。

6. **增加 debug 触发入口**
   - 在玩家 debug 面板增加测试战斗入口，便于开发期快速验证。

7. **补齐测试并回归**
   - 覆盖 TurnCore、BattleScene 流程、GameScene 切换协议。
