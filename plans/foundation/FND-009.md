## 已确认约束
- 本任务只做“可进入/可退出/可跑通回合”的战斗骨架，不做完整数值、技能、AI、掉落系统。
- 采用 **push/pop 栈模式**：`GameScene` push `BattleScene`，战斗结束后 pop 返回。
- `SceneManager` 当前约定为“只更新栈顶场景”（`fixedUpdate/update`），因此战斗期间 `GameScene` 会冻结。
- 在上述栈模型下，本任务 **不要求** 切换 `GameScene::GameMode::Battle`。
- 继续遵循 Command -> DomainEvent 边界（沿用 `FND-003`）。
- 采用最优方案实现，可重构，不考虑向后兼容。

## 目标
- 可从探索场景进入战斗场景，并在战斗结束后返回探索场景。
- 提供可扩展的 `TurnCore`（回合顺序、行动执行、胜负判定）。
- 跑通最小 `2v2` 回合流程（攻击/结束回合），并有测试保障。

## 范围
- 新增 `BattleScene`（UI、输入、回合驱动、结算退出）。
- 新增战斗领域核心（`TurnCore` + `BattleSession` 最小模型）。
- 新增探索 -> 战斗触发协议（先用 debug 命令触发，便于验证）。
- 保证返回探索后主场景状态稳定（不崩溃、不丢上下文）。

## 非目标
- 不实现技能树、状态异常、复杂 AI。
- 不实现完整敌人生成与地图遭遇系统。
- 不实现战斗中的存档/读档中断恢复。

## 实现思路（最优方案）
1. **战斗域核心先行（纯逻辑）**
   - `TurnCore` 负责回合顺序、当前行动者、回合推进、胜负判定。
   - `BattleSession` 负责动作执行与状态变更。
   - 二者均不依赖 `entt::dispatcher` / `registry`，保证可单测。

2. **BattleScene 只做编排和表现层**
   - 负责输入/UI、调用 `BattleSession`、显示回合结果。
   - 负责将 `BattleSession` 结果映射为项目事件（必要时经 dispatcher 发出）。

3. **切换协议明确采用 push/pop（非 replace）**
   - `GameScene` sink `EnterBattleCommand` 后 `requestPushScene(BattleScene)`。
   - `BattleScene` 完成结算后发出 `BattleEndedEvent` 并 `requestPopScene()`。
   - 采用 push/pop 的原因：返回探索时状态保留零成本，且与现有 `PauseMenuScene` 架构一致。

4. **明确 BattleScene 内部状态机（回合驱动而非探索每帧逻辑）**
   - `WaitingForInput -> ExecutingAction -> AnimatingResult -> CheckVictory -> NextTurn/BattleEnd`。
   - 首版 `AnimatingResult` 可为最小占位（短时延时或即时过渡），后续再替换为动画系统。

5. **命令与事件契约统一**
   - 战斗领域结构体放 `src/game/battle/battle_types.h`。
   - 进入战斗/提交动作/战斗结束等契约统一追加到 `src/game/defs/commands.h` 与 `src/game/defs/events.h`。

6. **测试策略分层**
   - 核心流程测 `TurnCore/BattleSession`（纯逻辑、快速、稳定）。
   - 场景层采用 smoke 风格测试（源码/接线约束），避免高成本 Context 全量 mock。

## BattleScene 状态流转（最小）
- `WaitingForInput`：等待玩家按钮输入（`Attack` / `EndTurn`）。
- `ExecutingAction`：调用 `BattleSession::submitAction()`。
- `AnimatingResult`：展示结果（首版可占位）。
- `CheckVictory`：检查是否胜负已定。
- `NextTurn`：未结束则推进到下一行动者并回到 `WaitingForInput`。
- `BattleEnd`：发送结算事件并 pop 场景。

## 分步骤实现
1. **定义战斗数据与命令契约**
   - 在 `battle_types.h` 定义 `BattleUnit/BattleAction/BattleResult`。
   - 在 `commands.h` / `events.h` 增加 `EnterBattleCommand`、`SubmitBattleActionCommand`、`BattleEndedEvent` 等。

2. **实现 TurnCore（纯逻辑）**
   - 实现出手顺序、行动后推进、死亡跳过、战斗结束判定。

3. **实现 BattleSession（纯逻辑应用层）**
   - 封装“执行动作 -> 更新状态 -> 产出结果快照”的流程，不直接依赖 dispatcher。

4. **实现 BattleScene（可推可弹）**
   - 构建最小 UI（当前回合方、血量、Attack/EndTurn 按钮）。
   - 按状态机驱动回合流转。

5. **接入 GameScene 入口与回退**
   - `GameScene` 显式 sink `EnterBattleCommand` 并 `requestPushScene(BattleScene)`。
   - 处理 `BattleEndedEvent`，确保返回探索时状态一致。

6. **增加 debug 触发入口**
   - 在玩家 debug 面板增加 `Start Test Battle (2v2)`，用于开发期快速验证。

7. **补齐测试并回归**
   - `TurnCore/BattleSession` 单测 + `BattleScene/GameScene` smoke/接线测试。
