### Phase 4: 后续增强 - Input Buffer / Glyph / Rumble / Rebind

**目标**：在前 3 个阶段稳定后，补齐手柄和多设备体验增强能力。

#### 实现思路

- 这一阶段不再重构核心动作流转，而是在稳定基础上做增强。
- 所有增强都以前 3 个阶段的语义动作和上下文模型为前提。

#### 需要新增的文件

- `src/engine/input/input_buffer.h`
- `src/engine/input/input_buffer.cpp`
- `src/engine/input/input_glyphs.h`
- `src/engine/input/input_glyphs.cpp`
- `tests/engine/input/input_buffer_test.cpp`

#### 需要修改的文件

- `src/engine/input/input_manager.*`
- `src/engine/debug/panels/input_debug_panel.*`
- 相关 UI 文案 / 提示渲染文件

#### Step 4.1: 输入缓冲

- 为需要高响应的系统补可选输入缓冲，优先服务战斗菜单和连招/确认类操作。
- 缓冲保留最近 N 帧或最近 T 毫秒的边沿输入。

#### Step 4.2: 按键图标与输入源展示

- 根据最近输入来源显示键盘/手柄提示。
- 为常见语义动作提供 glyph 查询接口，而不是在 UI 里硬编码按钮文本。

#### Step 4.3: 手柄震动

- 为确认、取消、命中、切换等行为提供有限的震动反馈接口。
- 震动应由语义事件驱动，而不是由某个物理按钮直接触发。

#### Step 4.4: 重绑定

- 在已有 binding 模型上扩展重绑定存储和运行时刷新能力。
- 优先支持动作级重绑定，不做设备专属魔改路径。

#### Step 4.5: 调试能力补强

- 在输入调试面板中显示：
  - 当前输入源
  - 活动手柄
  - 轴值
  - 缓冲区状态
  - 语义动作绑定结果

- [ ] 增加手柄震动接口

#### 完成标准

- 战斗和菜单类系统可以可靠消费短时缓冲输入。
- UI 能根据输入源显示合适的提示。
- 设备体验增强能力建立在统一语义动作之上，而不是新的临时分支。
