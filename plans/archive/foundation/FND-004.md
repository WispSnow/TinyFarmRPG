## 目标
- 为 `SystemScheduler` 增加“每帧阶段日志（trace 级）”，用于快速定位调度顺序与卡点阶段。
- 在 Game Debug 面板新增 scheduler 可视化，显示：
  - 当前 `GameMode`
  - 本帧/近几帧系统阶段耗时摘要
  - 实际执行阶段顺序（含 gate1/gate2 分支结果）
- 保证非 Debug UI 构建零额外开销；Debug UI 构建下在未开启采样时无计时开销。

## 范围
- 在 `SystemScheduler` 增加阶段前后回调能力（调度器不感知 profiler 类型）。
- 新增 scheduler 采样数据结构（环形缓冲、阶段耗时记录、帧摘要）。
- 在 `GameScene` 侧基于回调完成计时采样和 trace 日志输出。
- 新增 Game 侧调试面板展示 scheduler 状态与耗时摘要。
- 增加对应单测，覆盖采样结果与 gate 行为可观测性。

## 非目标
- 不引入通用全局 profiler 框架（仅覆盖 `SystemScheduler`）。
- 不调整现有 scheduler 的阶段定义和执行顺序。
- 不改动 `GameMode` 业务语义（`Battle/PauseOverlay/Cutscene` 仍维持当前占位策略）。
- 不引入文件落盘或远程 telemetry。

## 当前基线
- `src/game/runtime/system_scheduler.cpp` 已有 `on_stage_executed` hook，且调用时机在阶段执行前，不足以直接统计单阶段耗时。
- `src/game/scene/game_scene.cpp` 调用 `scheduler_->tick(...)` 时未传任何调试/分析数据通道。
- 现有 Game Debug 面板中没有 scheduler 相关窗口（`Player / GameTime / Inventory / SaveLoad / MapInspector / BlueprintInspector`）。

## 实现思路（最优方案）
1. **保持 `SystemScheduler` 纯调度，仅扩展回调契约**
- 将 `TickParams` 从单回调扩展为双回调：
  - `on_stage_started(SchedulerStage)`
  - `on_stage_completed(SchedulerStage)`
- `execute_stage()` 在阶段执行前后各触发一次回调，不引入 profiler 指针，不在 scheduler 内做计时逻辑。
- 若两个回调都为空，执行路径与当前版本等价。

2. **新增 Debug-Only `SchedulerProfiler`**
- 新增 `SchedulerProfiler`，放在 `game/debug/` 并仅在 `ENABLE_DEBUG_UI` 下编译：
  - 维护固定容量环形帧历史（建议 120 帧）。
  - 每帧记录：`mode`、`gate1/gate2`、`total_ms`、阶段序列与各阶段 `elapsed_ms`。
  - 提供查询接口（最近帧、最新帧、按阶段聚合平均耗时）。
- 采样默认关闭，由面板显式开启；关闭时仅保留空操作。

3. **GameScene 负责注入采样与 trace 日志**
- `GameScene::update()` 在 Debug UI 构建下：
  - 帧开始 `profiler.beginFrame(mode)`。
  - 通过 `on_stage_started/on_stage_completed` 回调驱动 profiler 开始/结束阶段计时。
  - `tick()` 返回后用 `TickResult` 结束帧并记录 gate 信息。
- 当 `spdlog` 级别为 `trace` 且本帧有样本时，由 profiler 输出单行帧摘要日志（mode/gate/total/分阶段耗时）。

4. **新增 Scheduler Debug Panel**
- 新建 `SchedulerDebugPanel`（Game 分类）并注册到 `GameScene`。
- UI 展示内容：
  - 当前 mode（直接展示本帧 mode）
  - 最新帧：总耗时、阶段数、gate1/gate2 是否触发
  - 阶段耗时表（按执行顺序显示）
  - 近 N 帧平均耗时摘要（用于观察抖动）
- UI 控件：
  - `Capture` 开关（绑定 `SchedulerProfiler::setEnabled`）
  - `Recent Frames` 数量（影响汇总窗口）
  - `Clear`（清空历史）

5. **测试收敛**
- 新增 `SystemSchedulerProfilerTest`：
  - 双回调可完整覆盖每个执行阶段（started/completed 成对）。
  - 采样开启时，能记录 stage 顺序、耗时和 gate 结果。
  - 采样关闭时，不产生历史记录。
  - 历史容量固定（环形覆盖）行为正确。
- 更新 `tests/CMakeLists.txt` 注册新测试。
- 执行全量回归。

## 风险与回滚
- 风险：
  - 每帧日志在 trace 级可能产生大量输出，影响排查体验。
  - 阶段前后回调若接线错误，可能导致计时边界错位。
  - 调试面板读取历史数据时若与写入生命周期处理不当，可能出现悬挂引用。
- 缓解：
  - 严格限定日志级别为 `trace`。
  - 采样默认关闭，必须显式打开；并限制历史容量为固定上限。
  - `GameScene::clean()` 统一注销 Game 面板，避免跨场景残留引用。
- 回滚策略：
  - 若出现回归，优先回退 `SchedulerDebugPanel` 与 profiler 接线，保留 scheduler 主流程不变。
