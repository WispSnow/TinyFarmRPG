## 目标
- 将存档 schema 从 `v2` 升级到 `v3`，并把“旧档迁移”显式收口为单一入口，避免后续字段扩展继续散落在读档逻辑中。
- 在 `v3` 预留后续系统所需存档位：`quest_state`、`skill_state`、`appearance_state`、`combat_state`（框架态，默认值）。
- 保证 `v2` 存档可加载并迁移到 `v3`，新档写入稳定为 `v3`。
- 对非法版本输入（缺少 `schema_version` / `schema_version=0` / 高于当前版本）保持明确拒绝与错误信息。

## 范围
- 升级 `SAVE_SCHEMA_VERSION`：`2 -> 3`。
- 新增独立迁移模块，统一处理 `v2 -> v3` JSON 规范化。
- 扩展 `SaveData` 与序列化/反序列化，增加四个新状态字段及默认值。
- 改造 `SaveService::loadFromFile`：读取原始 JSON 后先迁移到最新 schema，再进入 `deserialize/apply`。
- 新增迁移与回读测试，覆盖 `v2 -> v3` 与 `v3` 写回一致性。

## 非目标
- 不在本任务实现任务/技能/换装/战斗玩法逻辑，仅提供存档结构占位与默认语义。
- 不调整存档文件 IO 策略（临时文件写入与原子替换逻辑保持现状）。
- 不改 Scene 流程与 Save/Load UI 交互。
- 不引入“虚构 v1 格式兼容承诺”；若未来要支持 v1，需单独定义 v1 规范与任务。

## 当前基线
- `src/game/save/save_data.h:13` 当前 `SAVE_SCHEMA_VERSION = 2`。
- `src/game/save/save_data.cpp:185` `deserialize` 仅做“版本上限校验”，尚无显式迁移入口。
- `src/game/save/save_service.cpp:236` `loadFromFile` 当前流程是“读 JSON -> deserialize -> apply”，无 migration stage。
- `tests/game/save_slot_summary_test.cpp:22` 仅覆盖 slot 摘要读取（`schema_version=2`），没有迁移与存档回读一致性测试。
- 仓库历史中 save 模块初始版本即为 schema v2（`dac4589`），当前无已定义 v1 存档格式。

## 实现思路（最优方案）
1. 采用“迁移前置 + v3 规范化”的单入口方案。  
说明：旧档在进入 `deserialize` 前统一转换为 `v3` JSON；`deserialize` 仅面向规范化后的最新结构，避免读档路径长期堆叠历史分支。
2. `v3` 新增字段使用“强类型占位 struct + 默认 `{}`”策略。  
说明：新增 `QuestStateSaveData/SkillStateSaveData/AppearanceStateSaveData/CombatStateSaveData`（空 struct）；JSON 固定写入 `{}`，缺失时迁移器补齐 `{}`。
3. 迁移器接口保持稳定。  
说明：采用 `[[nodiscard]] bool migrateToLatest(nlohmann::json& json, std::string& out_error)`，就地迁移，后续 `v3->v4` 可在内部追加 step 而不改调用方。
4. 测试优先锁定迁移契约与核心数据完整性。  
说明：migrator 测试优先使用内联 JSON（`json::parse`）减少 IO 干扰；round-trip 测试必须校验关键字段值一致而非仅“不报错”。

## 风险与回滚
- 风险：
  - 旧档字段缺失/脏数据导致迁移失败。
  - 迁移器与 `deserialize` 双重兜底逻辑不一致，造成行为分叉。
  - 新增字段默认值不稳定，导致后续系统接入后出现“同档不同行为”。
  - 新增测试目标对 `nlohmann/json` 头路径依赖不明确，可能引发构建失败。
- 缓解：
  - 迁移器输出统一 `v3` 规范 JSON，`deserialize` 只走单一路径。
  - 关键迁移场景用测试夹具锁定（标准 v2、边界缺字段、非法 schema）。
  - 明确四个新增状态字段默认语义并落文档。
  - 新增测试后优先本地编译 `game_tests`，提前暴露头文件依赖问题。
- 回滚策略：
  - 若出现回归，优先保留测试与迁移模块，回退最近一次字段写入变更。
