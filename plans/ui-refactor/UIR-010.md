## 目标
- 修复以下缺陷：鼠标在“同一帧移入并按下”交互元素时，可能无法进入 `Pressed` 状态，导致释放时不触发 `clicked()`。
- 保持当前状态机架构与时序语义不变（仍为 `setNextState -> update` 延迟切换），仅做最小行为修复。

## 范围
- 仅修复 `UINormalState` 对按下事件缺失响应的问题。
- 仅涉及当前 `UIState` 三态（`Normal/Hover/Pressed`）路径。
- 补充对应自动化测试与回归检查项。

## 非目标
- 不改 `UIManager::onMousePressed()` 分发策略。
- 不改 `UIInteractive` 的延迟状态切换机制（`next_state_`）。
- 不引入 `InteractionPhase/transitionTo()`（属于 `UIR-020+`）。
- 不处理 `onReleased` 与取消路径（属于 `UIR-011`）。

## 当前基线与根因
- 帧时序：输入先于场景/UI 更新
  - `GameApp::run()` 中 `handleEvents()` 在 `update()` 前执行：`src/engine/core/game_app.cpp:62`, `src/engine/core/game_app.cpp:63`
  - `InputManager::update()` 先处理事件再触发动作回调：`src/engine/input/input_manager.cpp:99`, `src/engine/input/input_manager.cpp:110`
- 鼠标按下分发路径：
  - `UIManager::onMousePressed()` 直接 `target->mousePressed()`：`src/engine/ui/ui_manager.cpp:165`, `src/engine/ui/ui_manager.cpp:172`
  - `UIInteractive::mousePressed()` 仅转发给当前 state：`src/engine/ui/ui_interactive.cpp:226`
- 缺陷点：
  - `UINormalState` 只实现 `onMouseEnter()`，没有 `onMousePressed()`：
    - 头文件：`src/engine/ui/state/ui_normal_state.h:24`
    - 实现：`src/engine/ui/state/ui_normal_state.cpp:17`
- 结果：
  - 当元素刚被命中但还未完成 hover 状态切换时，按下落在 `NormalState`，不会进入 `PressedState`，后续 release 不触发点击。

## 方案与决策
### 选定方案（A）
- 在 `UINormalState` 增加 `onMousePressed()`，直接：
  - `owner_->setNextState(std::make_unique<UIPressedState>(owner_));`
- 优点：
  - 改动最小，语义闭合在状态机内。
  - 不影响 `UIManager` 与输入系统职责。
  - 与后续 `UIR-020+` 可平滑衔接（后续会整体迁移到 phase 状态机）。

### 拒绝方案（B）
- 方案：`UIManager::onMousePressed()` 先 `updateHovered(target)` 再 `mousePressed()`。
- 拒绝原因：
  - 当前状态切换是延迟生效：`setNextState()` 仅设置 `next_state_`，实际切换在 `UIInteractive::update()` 中处理。
  - 同一调用链内即使先 `mouseEnter()`，当前 state 仍可能是 `Normal`，不能可靠修复该问题。

### 调用顺序差异（预期行为，需显式记录）
- `Hover` 路径按下：`Normal -> Hover(enter) -> Pressed`，会触发 `hover_enter()` 与 hover 视觉。
- `Normal` 同帧按下（本任务修复后）：`Normal -> Pressed`，不会经过 `HoverState::enter()`。
- 预期结果：
  - 不触发 `hover_enter()` 回调（该路径本来就不经过 Hover）。
  - 不出现“一帧 hover 再 pressed”的视觉闪烁。
- 该差异是修复后的正确行为，不应被后续任务误判为 regression（尤其 `UIR-040/041` 回调机制收敛阶段）。

- `UINormalState` 显式处理 `onMousePressed()`。
- 同帧移入按下场景下，release inside 能稳定触发 `clicked()`。
- 既有 press/release 语义不回退（inside 触发 click，outside 不触发 click）。
- `Normal -> Pressed` 路径不触发 `hover_enter()` 被明确记录为预期行为。
- 定向测试与全量测试通过。

## 风险与回滚
- 风险：
  - 新增 `onMousePressed()` 后，`Normal -> Pressed` 与 `Hover -> Pressed` 可能出现行为不一致。
  - 后续迁移时可能把“未触发 `hover_enter()`”误判为回归。
- 缓解：
  - 保持两者都仅做 `setNextState(UIPressedState)`，由 `UIPressedState` 统一承担视觉/音效。
  - 在任务文档与测试注释中显式标注该差异为“预期行为”。
- 回滚策略：
  - 单任务小提交；若回归，回退 `UIR-010` 提交即可，不影响 `UIR-000/001` 基线资产。
