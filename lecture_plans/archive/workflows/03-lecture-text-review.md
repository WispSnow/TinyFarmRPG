# 阶段 3：课程文本审阅与扩写

> 目标：在代码修订已认可或确认无需代码修订后，审阅并扩写当前讲义，包括事实修正、结构优化、Mermaid 图、阅读清单、自测问题和练习。

## 前置条件

- 阶段 2 已经通过用户审阅 / 测试，或阶段 1 结论为无需代码修订。
- 当前讲义可以根据已确认的实现状态进行更新。

## 工作步骤

1. **读取上下文**
   - 当前讲义、课程大纲对应小节、事实账本、进度表。
   - 必要时读取上一期参考章节和项目文档。

2. **事实审阅**
   - 校验路径、类名、函数名、事件名、组件名、数据字段、Lua API、RML/RCSS、工具名。
   - 对真实代码片段逐段核对 `文件 + 符号`，并确认是否需要标注“节选”。
   - 对数字表述、版本表述和跨讲引用使用事实账本统一口径。

3. **大纲对齐**
   - 检查本讲目标、知识点、阅读清单、源码入口、自测问题、最小练习是否覆盖大纲承诺。
   - 若正文有意偏离大纲，记录原因；必要时提出是否同步更新大纲。

4. **课程扩写**
   - 优先补清楚关键链路、模块边界、状态变化、失败路径、观察入口。
   - Mermaid 图服务于理解，不为了凑数量。
   - 图中换行使用 `<br/>`，不要使用 `\n`。
   - 节点文字不嵌入 Markdown，避免 `1. ` / `2. ` 这类编号。

5. **练习与自测**
   - 自测题必须能从正文、源码或运行观察中得到正确答案。
   - 最小练习必须可执行，且不会引导学生修改错误路径。
   - “先看再讲”的观察入口要能落到真实面板、工具、脚本或测试。

6. **阶段验证**
   - 检查 Markdown 相对链接和源码入口路径。
   - Mermaid 优先用 `mmdc` 或可用工具解析；没有工具时说明只做人工结构检查。
   - 用 `rg` 检查已知过时表述是否残留。

## 输出格式

阶段 3 的回复应包含：

- **文本改动概览**：修正了哪些事实，扩写了哪些部分。
- **Mermaid 图**：新增 / 修改了哪些图，各自解决什么理解问题。
- **大纲对齐**：是否覆盖大纲目标，有无偏离。
- **验证结果**：链接、路径、Mermaid 检查情况。
- **等待确认**：明确说明等待用户审阅课程文本，通过后再进入阶段 4。

## 禁止事项

- 不改业务代码。
- 不把未执行的观察步骤写成已验证。
- 不让图示数量压倒教学清晰度。
- 不长期保留讲义与大纲的分叉。

## 进度记录

阶段 3 完成后，将 `lecture_plans/workflows/progress.md` 中当前讲次状态标记为“阶段 3 待审阅”，并记录文本改动、图示和验证范围。
